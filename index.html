Why it exists

Dental offices already run a whiteboard: a shared list of who's where and what's next. This replaces the physical one with a synced digital one — without asking a small office to stand up a server, manage accounts, or trust a cloud vendor with patient-adjacent scheduling notes.

🖧

LAN-only, no cloud

Every packet stays on the office network. No accounts, no external service, no internet dependency.

⚡

Zero configuration

Install it on every machine and it just finds the others. No IP addresses to type in, no setup wizard.

🔁

Self-healing hub

Instances elect a hub automatically. If that machine goes down, survivors re-elect a new one in seconds and reseed the board.

🪟

Runs on the machines you have

Ships as a single Windows executable — no installer, no admin rights required, no runtime to pre-install.

🎨

Per-machine themes

Seven built-in themes so each station can look how the office wants, with a Maize & Blue default.

🕒

Stale-entry highlighting

Entries left untouched past a configurable threshold visibly change color, so nothing sits forgotten.

How it stays in sync

Every install is identical. Instances find each other by UDP broadcast; the lowest hostname promotes itself to hub and serves the shared board over plain TCP. Everyone else connects as a client. A version counter makes the freshest board win on every merge, and additions are queued with an outbox so a message survives even if the hub drops mid-send.
